# 架构与实现边界

| 层 | 当前实现 | 主要约束 |
| --- | --- | --- |
| 文档 | C++20 持久化 AVL Rope，8 Ki UTF-16 单元叶块，子树长度和换行数 | 编辑重建路径，共享未变化节点；相邻小块合并 |
| 原生桥接 | Rope 快照 + Foundation 原生字符串镜像 + NSTextStorage | 主线程同步提交树、镜像和布局索引；UIKit 使用连续字符串，不经 Swift String 全文绑定 |
| 排版/输入 | UITextView + TextKit 2 + 有界文本元素 | 排版、输入法、辅助功能、选区手柄和编辑菜单由系统负责；长行按组合字符边界分段，超大表面只在视口内绘制 |
| 文件 | 独立 actor 中 64 KiB 读取/解码，分块保存 | UTF-8、带 BOM 的 UTF-16 LE/BE；保留 BOM、编码及原有换行 |
| 插件 | Sendable 请求、不可变文档快照、actor 插件 | 请求绑定 documentID/revision/视口/插件代次；过期结果不发布 |
| 高亮 | 数据驱动有限词法器，稀疏词法状态检查点 | 解析在后台，按屏幕内实际折行取范围，只将附近最多 64 Ki UTF-16 / 4,096 token 交给 UI |

高亮显示与词法有效性分开管理：编辑时保留上次的颜色，按每次真实存储替换同步移动 UTF-16 范围，插入内容暂时继承编辑位置的颜色。TextKit 2 重排会使 rendering attributes 失效，`renderingAttributesValidator` 从缓存同步恢复当前布局片段的颜色，不在排版回调中解析文本。后台结果通过文档、revision 和请求代次检查后，比较新旧颜色区段，只写回差异（包括 token 变回普通文本），在同一个主线程发布中完成。取消、过期或失败的请求不会清空已显示颜色；卸载全部插件或替换文档时明确清理。缓存仅持有最近一次视口请求的着色区段及其编辑映射，不累积全文或历史版本。重叠插件按后者覆盖前者处理，归并在后台完成。

这是显示层的增量更新；词法器仍使用稀疏检查点，尚未实现 VS Code 那种逐行 token 缓存与行末状态收敛后停止传播。跨行注释等语法发生变化时，旧颜色只作过渡，正确结果仍由后台插件产生。

压缩 JS 的长行按已完成排版的 `NSTextLineFragment` 与屏幕的几何交集请求高亮，不直接把 TextKit 的段落级 `viewportRange` 当作可见字符范围；通过二分查找跳过屏幕上方的折行，不强制排版屏幕外内容。请求范围按 2 Ki UTF-16 对齐并保留预读区，减少滚动时请求反复取消。词法检查点也可位于同一长行的 token 边界或带完整状态的注释/字符串内部，避免已解析的长行前缀在每次滚动时都从头扫描。

长段落的绘制表面与排版范围分开管理。TextKit 的默认绘制表面覆盖整个段落；数 MB 的压缩单行折行后可达到上百万点高度，即使选区与复制正常，也可能因为超大位图无法分配而显示空白。`TeakTextLayoutFragment` 对任一排版边超过 2,048 点、或排版面积超过 131,072 平方点的段落停止原生表面绘制（3x 屏幕下，这个面积的 RGBA 位图约 4.5 MiB，不计墨迹外扩）；判断只读取已测量的 `layoutFragmentFrame`，避免滚动时反复计算涉及整段所有折行的精确墨迹边界。普通段落仍走原生绘制。

参考 STTextView 的片段视图复用与预读区思路，`TeakTextRenderView` 是不绘制的容器，使用固定在文档坐标中的 256 点高透明分块，并在视口上下各保留半屏预读区。滚动只移动已有位图，新进入范围的块才绘制，离开的视图清除旧 `layer.contents` 后进入有界复用池；不会每帧重画整屏，也不会创建整段位图。各块用已排版的 `NSTextLineFragment` 绘制，接缝处保留邻行墨迹。文档替换清空绘制块和整个复用池，释放上一份文档的行对象与位图；文字编辑及宽度变化清理旧块并复用轻量视图；高亮提交只重画字符范围与颜色差异相交的块。布局回调可刷新 TextKit 行对象而不丢弃仍有效的位图。分块不接管触摸或辅助功能，不改文档、折行、选区坐标或词法缓存；所有发布在同一主线程完成。文件首次打开仍有文档解码与初始排版成本，真机滚动、输入、选区手柄和放大镜行为仍需验收。

编辑链路使用 `TTTextContentStorage` 将每个源段落拆成目标不超过 4,096 UTF-16 单元的布局元素，边界向完整组合字符的末尾扩展，不拆开 emoji、组合字符或 CRLF。短段落保持原状；长行在片段接缝处可能提前自动折行。各元素的范围仍是原始文档的 UTF-16 坐标，不插入换行或其他字符，逻辑行号、词法状态、复制与保存继续使用原文。`TTTextParagraph` 明确提供实际内容和分隔符的文档范围。

每次真实字符替换先同步更新布局索引，只重建编辑位置及相邻元素，后续元素保留对象身份、移动源范围，使 TextKit 可以复用它们的折行。原生 `NSTextContentStorage.processEditing` 必须完整保留，由系统更新输入上下文、段落缓存和选区；仅调用 `recordEditAction` 不能代替这条链路。移出的元素强引用保留到原生编辑处理及显式布局失效完成后再释放，避免 TextKit 的弱引用指向已释放内容。没有定时器、延迟输入或编辑结束后再补排版的旁路。

UIKit 的段落/词边界查询和 Core Text 排版使用 `TTTextStorage` 持有的 Foundation 原生可变字符串镜像；每次编辑与树快照在同一个主线程提交中同步更新。镜像增加一份全文字符存储（一份约 2.58 MB 的压缩 JS 约需 5 MB UTF-16 字符空间），避免系统反复通过自定义 NSString 读取树。后台插件、文档快照和文件保存仍使用不可变 Rope。原生请求的 attributed substring 同时保留对应属性，不向原生排版器暴露可变镜像。

内存指标是整个进程的 `phys_footprint`，包括文档、UIKit、TextKit/Core Text、键盘、字体和绘制表面；`chunks` 只统计 Rope 叶块，不是布局片段或位图数量。317 个约 8 Ki UTF-16 的文档块及原生字符串镜像合计约 10 MiB 字符数据，不应按进程总内存除以块数估算每块大小。字体/键盘缓存及分配器释放后的可重用页也可能使进程占用高于刚启动时。

存储节点全部通过 `std::shared_ptr<const Node>` 和 `std::shared_ptr<const std::u16string>` 管理。只读数据切片使用 `std::span`，没有裸 `new/delete`、裸 C++ 所有权指针或手工分配。Foundation ABI 所要求的字符缓冲指针局限于 Objective-C++ 桥接方法，缓冲由标准库 RAII 对象拥有；Objective-C 对象使用 ARC。树无父指针与引用环。

文件不是整份先读成 Data/String，也不是每行一个字符串。保存持有不可变快照，逐块编码到同目录独占创建的临时文件，完成同步写入后原子 rename；错误或提交前取消会删除临时文件。保存期间的新编辑仍显示为未保存。UTF-8/UTF-16 解码会保留跨块字符和代理项，不做换行归一化。UTF-32、其他编码和二进制文件会报错。当前不提供外部文件修改冲突检测、文件版本合并或长期安全书签管理。

这里的高性能设计减少了应用自身的全文复制与重排；仍需实测 UIKit/TextKit 2 在目标 iOS 版本上的排版和菜单成本。当前不是 mmap、按需加载全部文件索引的超大文件编辑器：打开时仍会解码整份文件，常驻 UTF-16 文档，原生布局也可能缓存额外数据。极长单行、数百 MB 文件及百万行文件尚未建立真机性能指标。全选后再点击是否满足目标，必须以 iPhone 实测为准。

## 大选区几何

大选区的几何查询另外处理：`firstRect(for:)` 用原生行 tokenizer 限定到首个显示行，符合该接口只返回首行矩形的约定；当前超过 4 Ki UTF-16 的选区，`selectionRects(for:)` 只生成与 TextKit 当前视口（含预读及完整布局元素）相交的显示矩形，再交给系统的选区显示组件。选区本身不截断，文字读取、复制、剪切、保存及其他范围的几何查询保持原路径。包装原生矩形时保留坐标、书写方向、竖排和 transform，只有真正的原选区端点才报告 `containsStart/containsEnd`，不把裁剪边界误报为原选区端点。滚动和宽度变化在原生布局之后刷新选区显示，视口范围暂不可用时不在布局回调中强制排版整份文档。

`TeakTextTouchSupport` 集中封装 UIKit 可选能力探测。仅在主线程、大选区和原生方法签名匹配时采用系统已有的分段选区命中路径；未知签名保留原有路径。该兼容封装涉及私有 UIKit selector，按系统版本持续验证。
